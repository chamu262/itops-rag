IT Operations : SaaS App Onboarding Checklist (SAML / SCIM)

Created by Identity & Access, last modified on Jul 28, 2026

Use this checklist for every new SaaS application that will hold Kestrel data or need staff accounts. Create a HELP ticket of type SaaS onboarding and copy the checklist into it. Technical standard: CF-002.

1. Intake

  • Business owner team and cost centre named
  • Data classification of data the app will hold (Public, Internal, Confidential, Restricted)
  • Number of users and which groups
  • Vendor security documentation received (SOC 2 Type II or ISO 27001, DPA, sub-processor list)

2. Security review (Security Operations)

  • Vendor risk questionnaire completed; result Low or Medium, or accepted by the CISO
  • Data residency acceptable (EU for Confidential customer data)
  • Audit log export available for Confidential or Restricted apps

3. SSO configuration (Identity & Access)

  • Enterprise app created in Entra from the gallery if available, named <App> (KC)
  • SAML: Identifier (Entity ID) and Reply URL (ACS) from the vendor; NameID = UPN; SHA-256; certificate notification email set
  • OIDC: redirect URIs exact, no wildcards; client secret or certificate expiry recorded
  • Assignment required = Yes, group SG-App-<App> created and assigned
  • Local password login disabled in the app except one vendor break-glass account (credentials in the Security Operations vault)
  • Test sign-in by IdP-initiated (My Apps) and SP-initiated flows
# Find the enterprise app and its signing certificate expiry (Graph PowerShell)

4. Provisioning (SCIM)

  • SCIM endpoint and token from vendor; token expiry recorded in the SaaS register
  • Attribute mapping: userName = UPN, active = accountEnabled, name and email
  • Scope: Sync only assigned users and groups
  • Deprovisioning tested: removing a test user from the group deactivates them in the app within one cycle
  • No SCIM support: app added to the manual leaver list used by RB-GEN-002 step 8

5. Go-live

  • Conditional Access coverage checked with the What If tool
  • App added to the SaaS register with owners, SSO type, SCIM yes/no, certificate and token expiry dates
  • Users informed; app visible in My Apps; access request path in Self Service or the portal

Common failures during testing: AADSTS50011 (reply URL mismatch), AADSTS50105 (user not assigned), AADSTS75011 (requested authentication context). See VND-003.
